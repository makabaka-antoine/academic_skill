# Source formats and editable files

- **UTF-8 text and Markdown.** Read the complete editable passages. Preserve code, fenced blocks, YAML, link destinations, citations, table structure, headings and ordering unless a requested format change affects them. Repair a genuine textual problem within authorized captions or headings. For garbled text, identify the encoding from a BOM or other evidence, retain the original, and compare a decoded preview. Never replace unreadable characters in research content with guessed ones.
- **LaTeX fragments and projects.** Identify the actual entry file and included sources when a full project is requested. Preserve math mode, macros, labels, bibliography keys, source comments, cross-references and preamble. A caption or `\emph{}` argument can contain editable prose. Inspect the changed source with references in place. If a build is required and the declared compiler is available, use the project's engine and bibliographic backend, inspect its log and open the resulting pages. For a fragment, deliver editable TeX and mark build status only when relevant.
- **PDF inputs.** Read the actual PDF. Use `pdftotext -layout` or the declared text extraction tool. Compare critical passages to page images when extraction may confuse columns, rows, hyphenation, superscripts or signs. Use local OCR for scanned pages and verify ambiguous glyphs visually. Keep a page plus excerpt or section/paragraph locator for each adopted quote, value or finding. Extract into the work area. A PDF label or suggested abstract is insufficient evidence of the body.
- **Existing Office documents.** Use the case's native editor or a suitable OOXML tool to edit a copy in place. Preserve paragraph and run styling, fields, equations, comments and revisions as required. Verify actual Word revision elements when tracked changes are requested. Render the edited copy with the case's Office renderer and inspect the preview. Use the new-document route below when the task calls for authoring a new Word document.
- **Long or mixed inputs.** Batch by section or paragraph boundaries and preserve original order and the exact text of skipped units. Carry confirmed terms, definitions, protected facts and open items across batches. Recheck the assembled artifact. Keep source and candidate copies distinct. Use a narrow fallback on unreadable, conflicting or noneditable items and finish all unaffected units.

## Author and preview a new Word document

Save the reviewed UTF-8 manuscript in the work directory. Resolve the writer and renderer through the case's `environment/resources.yaml` and the installed tools. The helper runs with Python 3.10 or later using the standard library and the applicable writer below. Use the filenames required by the live case.

~~~sh
python3 /skills/weekly-skill/scripts/render_delivery.py /app/work/revised.md \
  --docx /app/output/revised.docx --pdf /app/output/preview.pdf --work-dir /app/work
~~~

- `python-docx` supports plain text, plain Markdown paragraphs and ATX headings. Use sandbox-capable Pandoc for richer Markdown or a DOCX style reference. Use `--pandoc` with an explicit installed path if needed and `--reference-doc` with the supplied DOCX to apply its style and document defaults. Check the resulting layout and any template requirements. Templates with placeholders or required existing document structures need the case's native editor.
- For PDF, the helper looks for `soffice` or `libreoffice` and uses an isolated profile. Pass `--soffice` to select the declared executable. If the case supplies a different tool, use it directly or pass `--renderer` for a declared native executable or Python adapter that accepts an input DOCX path and an output PDF path as two arguments. Use the declared tool's actual interface and select adapter code only from trusted runtime resources.
- Exit code `0` reports an editable DOCX and a generated PDF. Open both files. Compare the Word content to the reviewed draft and inspect each rendered page for clipping, missing glyphs, misplaced markers, and broken layout. Use the declared PDF rasterizer if needed. Complete the case's visual review before recording completion.
- Exit code `1` reports a valid editable DOCX with a preview issue. Try the available native renderer on that DOCX and preserve it if preview generation remains unavailable. Exit code `2` means the helper produced no usable Word artifact. Preserve any reviewed prose that the case allows as partial work. Record the actual issue and name only checked artifacts from the current run in the case result.
