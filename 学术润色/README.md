# 学术语言润色

`academic-language-polish` 1.0.0 面向已有学术文本的润色、校对、翻译和稿件一致性检查。它把编辑决定落在原稿的具体句子上，让改文、原文、理由和支撑材料对得上。

## 安装与使用

1. 在支持 Agent Skills 的环境，将本目录作为 Skill 加载。保留 `SKILL.md` 与同级 `references/`、`scripts/`、`assets/`、`examples/` 的相对位置。Harbor 将这些文件安装到它的 Skill 目录。
2. 给出可编辑的草稿或原始材料，指明目标文本、语言、用途和期望格式。有已确认术语或格式规则时一并提供。可显式调用 `$academic-language-polish`，也可在聊天中直接提出“润色下面的 Results，保留限定语、数字和引用”。校对模式返回问题和定位，编辑模式返回可编辑的完整请求范围和逐句修改记录。
3. 文件编辑可通过 Python 3.10+ 标准库脚本定位、应用和复查。直接对话仍可按同一证据和语义标准处理。PDF、OCR、Office 渲染及 LaTeX 编译取决于案例需要和宿主实际提供的工具。缺少工具或材料时交付可用范围及具体缺项。
4. 赛题执行时使用当次 `case.json` 的 `output_contract`，实际产物写入 `/app/output`。入口链接的 Harbor 指引给出读稿、暂存、部分交付和最终核对路径。正式案例和对照运行由平台生成。

可先阅读 [最小调用示例](examples/minimal.md)。[术语表样例](assets/glossary.example.tsv) 和 [风格输入样例](assets/style.example.json) 是用户可替换的示例。风格 JSON 由 Agent 读入，脚本参数只读取 TSV 术语表。

## 方法与验收

| 方面 | 可核验产物 |
|---|---|
| 完整性 | 原请求的可编辑范围完整返回。逐句改动可在源文件和改稿中分别定位。 |
| 正确性 | 同一数据及其对象、方向、时间、单位、限制和引文一致。可选脚本先找可观察的变动，再逐句读原文和证据。 |
| 可核验性 | 修改 ID、来源位置、原句、改句、分类和理由。材料缺失、判断待定、执行失败有明确影响范围。 |
| 效率 | 同一源快照批量定位修改，保留未改段落，合稿后回扫术语。评价时记录人工返修条目、已用轮次和待解决项。 |
| 增益与创新 | 用同稿、同术语表、同规则和同一评分口径比较。分开检查语言、保真、覆盖和可回溯性。复跑示例可验证脚本是否拦截数值替换和歧义定位。 |

通用语法工具适合标记句子问题，翻译工具适合提供目标语候选，人工编辑负责学科语义和修改取舍。这个 Skill 把候选和原稿版本、实际改动及保护项绑定，提供按句复核的材料。实际效益需要同条件对比。发布维护时记录版本，重跑示例与反例。包内规则、示例与代码为本提交原创实现。所参考的学术润色 Skill 与知识包用来识别失效方式，运行无需读取这些资料。

[审计命令与局限](references/audit.md) 说明字段、退出码和覆盖范围。投稿规范、引用是否支持原句、作者语义和渲染效果以实际证据核查为准。
