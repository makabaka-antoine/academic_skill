- 赛题：阅读 14｜Nanopublication（`product-arena-09-0e8befd4`）
- Skill：`nanopub-evidence`
- 版本：1.0.0
- 主方向：将科研材料拆分为可独立核查的原子断言，绑定最小充分证据和来源版本，并导出 JSON、JSONL、CSV 与未签名的四命名图 TriG 草稿
- 提交入口：本目录根路径的 `SKILL.md`

## 提交范围

本目录是一个完整、独立的 Skill，也是实际提交根目录。应提交以下内容：

| 路径 | 用途 |
|---|---|
| `SKILL.md` | Agent 调用入口、工作流程、输入输出和异常处理 |
| `scripts/` | 准备、证据定位、断言审查、导出、验证及合成回归脚本 |
| `references/` | 字段字典、受控关系、来源元数据和复核方法 |
| `examples/` | 明确标注的合成论文、20 条示例断言及示例输出契约 |
| `README.md` | 安装、依赖、完整调用、输出、最小示例、限制和自查方法 |
| `GITHUB_URL.txt` | 本题 GitHub 公开作品地址及提交根内入口 |
| `提交说明.md` | 本提交范围、实测记录和上传验收说明 |

不要加入 `demo-output/`、`__pycache__/`、`.pyc`、外层 ZIP、其他赛题材料、组织方正式案例、白板或预先生成的正式答案。示例中的模型、人员、数据和结果均为虚构演示，不得作为正式案例成绩或真实科研证据。

Harbor 评测时，将本目录内容作为 `/app/submission/`，使入口位于 `/app/submission/SKILL.md`。平台安装后通常从 `/skills/weekly-skill/SKILL.md` 加载。运行时读取 `/input/case.json`、`/input/task.md` 和实际科研材料，中间文件置于 `/app/work`，最终结果置于 `/app/output`。最终 `result.json` 必须保留 `case_id`、原 `output_contract` 字段、真实状态、来源、不确定性和变更记录。

## 本地使用与自查

文本流程需要 Python 3.9 或以上，核心文本处理和固定格式导出使用标准库。PDF、OCR 和独立 TriG 解析依赖见 `README.md`；平台环境的版本和路径以当次 `environment/resources.yaml` 为准，本包未提供可选第三方依赖的锁定版本。

从本目录运行：

```text
python scripts/np_evidence.py doctor
python scripts/selftest.py
python scripts/selftest.py --demo --out demo-output
```

`demo-output` 是本地运行产物，不应混入提交包。也可以使用一个不存在或为空的外部输出目录。完整逐命令调用、字段构造、PDF 页面复核及失败处理见 `README.md`、`references/field-dictionary.md` 和 `references/review-method.md`。
